# CyberSegyrudad — JorgeVanne

**Un laboratorio de aprendizaje, ingeniería e investigación en seguridad informática.**

**Integrantes:** Jorge Peña - Vannesa Pulido

## Nuestra misión

Desarrollar progresivamente la capacidad de **comprender, construir, evaluar y mejorar sistemas computacionales seguros**. Comenzamos desde los fundamentos de Linux y redes, aprovechando nuestra experiencia previa como desarrolladores; más adelante profundizaremos en AppSec, Web3 y áreas de investigación como análisis de programas, verificación formal, criptografía, seguridad de protocolos y sistemas.

**No limitamos el objetivo a pentesting, bug bounties o empleo.** Nos interesan también la investigación original, el desarrollo de herramientas, las matemáticas aplicadas y la contribución a tecnologías de seguridad.

## Cómo trabajamos

1. **Aprender:** estudiar documentación primaria, libros técnicos y materiales universitarios.
2. **Aplicar:** ejecutar laboratorios legales, programar, experimentar y recopilar resultados.
3. **Demostrar:** explicar mecanismos, escribir pruebas y defender técnicamente conclusiones.
4. **Documentar:** elaborar notas con referencias verificables y bitácoras individuales.
5. **Investigar:** formular preguntas propias, contrastar hipótesis, reproducir resultados y construir herramientas.

## Rutas de estudio

| Ruta | Estado inicial | Objetivo |
| --- | --- | --- |
| Fundamentos: Linux, redes, sistemas, HTTP | Inicio | Construir un modelo correcto del funcionamiento de sistemas |
| Web Application Security | Posterior a fundamentos iniciales | Evaluar y construir aplicaciones y APIs seguras |
| Web3, Solidity, EVM, wallets | Progresiva | Analizar contratos, firmas y protocolos financieros |
| Matemáticas e investigación | Transversal y creciente | Desarrollar métodos, modelos y herramientas originales |

No existen plazos rígidos: se avanza mediante evidencia de competencia, no por completar un calendario.

## Colaboración y evidencias

- Cada participante mantiene apuntes y ejercicios identificables.
- Usamos **Issues** para tareas, **branches** para cambios y **Pull Requests** para revisión mutua.
- Los writeups incluyen objetivo, contexto, comandos, evidencia, explicación, fuentes y aprendizajes.
- No se afirma que un laboratorio se completó sin una prueba verificable.
- Toda actividad ofensiva se realiza únicamente sobre laboratorios o sistemas autorizados.
- Nunca se suben contraseñas, cookies de sesión, tokens, llaves privadas, frases semilla, datos personales ajenos ni exploits no divulgables.
